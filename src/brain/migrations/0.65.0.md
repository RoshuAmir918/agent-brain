Goals now have ids and visible progress. They are the reason for unasked work; instructions to you are responsibilities.

1. Run `brain install-skills`. Read the updated recall Goals section, then your person's `Goals.md`. In an organisation vault, leave personal goals alone and skip to validation.
2. Run `brain goals migrate --dry-run`. Judge each legacy Active entry: what the person is trying to become or reach stays a goal; an instruction to you belongs to a responsibility. Find its existing hub first (for example, saving money may already be Ledger). If none exists, use `brain responsibility` to create its hub, skill and records; carry its existing permission, never invent a new grant or schedule.
3. Run the dry run again with one `--responsibility "<exact legacy title>=<existing hub>"` per instruction, then the same command with `--apply`. The helper assigns ids in file order, keeps explicit words, dates and evidence, moves instructions to their named hubs and archives the entire original. Unknown dates stay unknown; empty templates stay empty. For each moved instruction, run `brain needs-you --confirm "<what you treated as standing work, in plain words, so they can correct it>" --source <hub>`.
4. Review each converted goal with `brain goals show G-n`. Correct kind (`edit --kind reach|become`), title, words or finish date through the command; do not infer dates. Link only open tasks and hubs clearly serving it: `brain task T-nnn set --goal G-n`, `brain goals G-n link <hub>`. Leave unclear links alone. Link prepared drafts and works when equally clear.
5. Run `brain validate`, fix what it names, then `brain compile-context --write` and `brain migrate-done`. The updated recall or morning skill asks the capture question at most once, in conversation or briefing, never during this migration.
