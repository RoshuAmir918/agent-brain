Responsibilities and the improve routine.

The engine now says how standing work is held: a responsibility has a hub note at the vault root (`skill:` and `records:` in its frontmatter), an own skill, and a records folder under the Hermes home. `brain responsibility "<Name>" --skill <name> --records <folder>` builds the set; `brain validate` reports an own skill without its hub. A new core routine, `{prefix}improve`, runs each morning before the briefing: it studies one responsibility as a practitioner and writes a recommendation to the hub, and it proposes new responsibilities from yesterday's digest. The recall skill has the rules, including when you may edit an own skill.

Do this without the owner:

1. `brain update` once more, then `brain install-skills` and confirm `{hermes_dir}/skills/{prefix}improve/SKILL.md` exists.
2. For each own skill under `{hermes_dir}/skills/` (one the package did not render), run `brain responsibility "<Name>" --skill <its folder name> --records <its records folder>` with a name for the work itself, not the mechanism. Fill Objective, Permission and Strategy from what the skill and its dated notes already say; leave Weaknesses with what you know; leave Improvements empty. The existing skill is not overwritten.
3. Add `Improvements` to `log_dirs` in `brain.toml` only if it is not already handled: the engine treats `{agent_dir}/Improvements/` as a ledger folder by default.
4. Create the job one hour before your morning briefing: `hermes cron create "0 7 * * *" "Run Improve." --skill {prefix}improve --workdir $VAULT_REPO --deliver local --name improve`, adjusting the hour, then add its line to the cron table and the routines table in `{hermes_dir}/README.md`.
5. `brain validate`, commit `chore(brain): add responsibility hubs and the improve routine`, push, then `brain migrate-done`.
