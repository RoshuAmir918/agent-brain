# Hermes deployment

How the agent runs on Hermes Agent with this vault as its memory. The memory model is in [[memory/agent/Memory Spec|Memory Spec]]; this note is the wiring. Verify flags with `hermes --help` on your machine, since the CLI moves.

## What Hermes provides and what the vault provides

| Need | Hermes | Vault |
| --- | --- | --- |
| Identity | `~/.hermes/SOUL.md`, loaded every session | `agent/SOUL.md` is canonical; `refresh.sh` copies it over whenever it changes |
| Session-start context | `.hermes.md` at the git root, injected as project context | Generated by `brain compile-context` from START, CURRENT, Triggers, open tasks, the Hot Set and a names-only directory of every hub, person and open task; `refresh.sh` regenerates it hourly |
| Agent scratch and user profile | `MEMORY.md` and `USER.md`, small and frozen in the prompt | Keep MEMORY.md for environment facts. USER.md gets a short summary of `human/Profile.md`; the profile stays the source |
| Procedures | Skills in an external dir, invoked as `/name` | `memory/hermes/skills/` is the external dir; the skills are rendered there from the engine package by `brain install-skills` |
| Episodic memory | `state.db` with full-text search and the `session_search` tool | `Conversations/Sessions/` is the nightly export, cold, for rebuilds and git history; `Conversations/Digests/` is one file per day of what you and the agent said |
| Scheduling | `hermes cron` | The night and day routines below |
| Long-term memory, decay, triggers, attribution | none | The vault and the `agent-brain` package (`brain` CLI) |

## One-time setup

The agent can do most of this itself from the bootstrap context file at the repo root; these are the steps it follows.

1. Clone this repo to a stable path, for example `~/brain`, and export `VAULT_REPO=~/brain` in the shell Hermes runs from. Python 3.11+. Install the engine: `pip install -e .` from the repo, or `pip install git+https://github.com/RoshuAmir918/agent-brain`. `brain --help` must work from the repo root.
2. Start the gateway from the repo root so project context resolves: `cd $VAULT && hermes gateway`. Hermes loads only one project context file and prefers `.hermes.md`.
3. `brain install-scripts` puts the two cron scripts into `~/.hermes/scripts/`; `brain install-skills` renders the skills into `memory/hermes/skills/`. Then run `~/.hermes/scripts/refresh.sh` once: it writes `.hermes.md` and copies SOUL into the Hermes home. After a `pip install -U`, rerun `brain install-scripts`; skills re-render themselves on the next hourly refresh.
4. Config (`hermes config set` or `~/.hermes/config.yaml`):
   - `skills.external_dirs: [$VAULT_REPO/memory/hermes/skills]` (the path `brain install-skills` prints)
   - `sessions.auto_prune: false`, or a retention well past 90 days. Nothing is deleted before export.
   - `sessions.max_export_messages`: raise it so long sessions export whole.
   - `memory.write_approval: false`, `skills.write_approval: true`.
   - Your messaging platform's home channel set to your DM with the agent, so `--deliver` reaches you.
5. Set `human_name` and `agent_name` in `brain.toml`; the digest labels turns with them. The same file holds the folder names, so the engine serves any layout.
6. Create the cron jobs below. Create one first, run `hermes cron list`, and confirm the next-run time is in your timezone; the docs do not say which timezone a cron expression uses.
7. Verify: `hermes skills list` shows the `brain-*` skills; a fresh session can quote the `.hermes.md` header; `hermes sessions stats` lists your platform after the first message.

## Session export

`export-sessions.sh` (installed by `brain install-scripts`) exports every session as markdown into `Conversations/Sessions/` and the complete jsonl into `Conversations/Sessions/all.jsonl`, builds `Conversations/Digests/<date>.md` with `brain digest`, commits `archive(<date>)`, pushes, then calls `refresh.sh`. Deterministic, no model. These files are `kind: log`, cold, never indexed; the agent reaches them by `session_search` or grep.

## Context refresh

`refresh.sh` pulls the vault, re-renders the skills from the installed package, regenerates `.hermes.md`, copies `agent/SOUL.md` into the Hermes home when it differs, and commits `context(<date>)` only if the context file changed. Hourly, and after the export. An edit you make anywhere reaches the agent's next session within the hour, and a failed night never leaves stale context.

## Cron jobs

Schedule and prompt are positional; `--skill` attaches the skill; `--workdir` is required or the job runs detached from the vault; `--deliver` sets where output goes. Times are examples; move them to suit your sleep.

```sh
V=$VAULT_REPO
hermes cron create "30 0 * * *" --no-agent --script export-sessions.sh --deliver local --name session-export
hermes cron create "15 * * * *" --no-agent --script refresh.sh          --deliver local --name context-refresh
hermes cron create "30 1 * * *" "Run attribution for yesterday."       --skill brain-attribute --workdir $V --deliver local --name attribution
hermes cron create "30 2 * * *" "Run Sleep 1 for yesterday."           --skill brain-sleep1    --workdir $V --deliver local --name sleep1
hermes cron create "30 3 * * *" "Run REM."                             --skill brain-rem       --workdir $V --deliver local --name rem
hermes cron create "0 4 * * *"  "Run Sleep 2."                         --skill brain-sleep2    --workdir $V --deliver local --name sleep2
hermes cron create "0 6 * * *"  "Run the People review."               --skill brain-people    --workdir $V --deliver local --name people
hermes cron create "0 8 * * *"  "Run the morning briefing."            --skill brain-morning   --workdir $V --deliver slack --name morning
hermes cron create "0 12 * * *" "Run the midday review."               --skill brain-midday    --workdir $V --deliver slack --name midday
hermes cron create "0 20 * * *" "Run the evening review."              --skill brain-evening   --workdir $V --deliver slack --name evening
hermes cron create "0 * * * *"  "Run the watch guard."                 --skill brain-watch     --workdir $V --deliver slack --name watch
hermes cron create "30 8-22/2 * * *" "Run the explore pass."           --skill brain-explore   --workdir $V --deliver slack --name explore
```

Replace `slack` with your platform. Jobs that have nothing to say produce no message; the skills say so, because delivery sends whatever the job outputs. Hermes disables cron management inside cron runs, so a skill cannot schedule more jobs.

## The routines

| Skill | When | Owns |
| --- | --- | --- |
| brain-recall | every substantive request | how the agent looks things up and writes small daytime updates |
| brain-attribute | 01:30 | which notes yesterday's replies relied on |
| brain-sleep1 | 02:30 | consolidating yesterday into memory, tidying hubs, running the script |
| brain-rem | 03:30 | one dream |
| brain-sleep2 | 04:00 | retrieval audit, reflections, the morning agenda |
| brain-people | 06:00 | profiles |
| brain-morning | 08:00 | the briefing |
| brain-watch | hourly | urgent items from the last hour |
| brain-midday, brain-evening | 12:00, 20:00 | register accuracy |
| brain-explore | every two hours, daytime | own inbound plus one proactive thread |

This table is the declared schedule. Sleep 2 compares it with `hermes cron list` every night and the morning briefing reports drift. The agent changes the schedule only when the owner asks, in conversation: it records the request, updates this table, and applies it. Delete what you do not want; add a routine by copying a skill and adding a line here.

## Verifying a night

`git log --oneline --since=yesterday` should show `archive`, `attribution`, `sleep1`, `rem` and `sleep2` commits for the date, plus `context` commits whenever a source note changed. The morning skill reports any missing stage. After the first night, open `Conversations/Digests/<date>.md` and check that the agent's turns carry `reads:` lines; if they are empty, the tool-call field names the parser assumes (see `docs/engine.md` in the engine repo) differ from your Hermes version.
